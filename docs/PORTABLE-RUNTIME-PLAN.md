# 跨平台脚本运行层与终端体验规划

日期：2026-09-05。代码核对基线：`33d9cc1`。

状态：研究与实施规划。R01 的能力报告、R06 的首批 Shell 基础库、R07 的行式菜单示例和 R12 的基础契约测试已部分落地；R02 的 launcher 合并、R04 的可信下载、R05 的完整终端适配仍在规划中。沿用现有 BusyBox + Cosmopolitan、full/min 发布方向；具体缺陷修法继续参照 [整改方案](REMEDIATION-PLAN.md)，测试取证沿用 [CI 方案](CI-REAL-RUNNER-EVIDENCE.md)。

## 1. 交付目标

让脚本作者使用少量稳定接口完成文件处理、下载、任务执行与终端交互。普通用户解压后可以启动，遇到能力限制能看懂原因，并获得可用的替代操作。同一脚本在不同平台执行相同业务逻辑，明确保留权限、文件系统和进程模型的真实差异。

首个版本支持三种交互方式：

| 模式 | 用户体验 | 前提 |
|---|---|---|
| 非交互 | 参数输入、稳定结果、可重定向日志；缺参数时立即报错 | 普通输入输出流 |
| 行式交互 | 编号菜单、逐行输入、确认与进度摘要 | 可交互终端；不要求 raw 输入 |
| 全屏交互 | 方向键、搜索、选择、滚动、窗口缩放 | 经验证的输入后端、光标控制和终端恢复 |

行式交互与全屏交互共享业务代码、选项 ID、默认值和返回结果。颜色单独控制，行式界面也可以有颜色。能力不足时降级显示方式；下载校验、文件权限等业务保证不能通过降级偷偷减弱。

## 2. 当前证据与需要修正的认识

| 已核对的事实 | 影响与后续动作 |
|---|---|
| `scripts/bb.sh` 与 `install.sh` 内生成的 launcher 仍是两套实现，缓存键、锁、loader 参数不同 | 零安装通过不能证明安装后通过；合并实现，并测试两种入口 |
| `bb.sh` Windows 分支使用精确字符串匹配；安装器使用 `mingw*` 等模式 | 对真实 Git Bash/MSYS `uname` 输出补回归，统一平台识别 |
| `tests/ci-platform-probe.py` 的 termios 探针只测 Unix PTY 的 erase；工作流为报告项 | 不足以宣称 raw、Ctrl-C、粘贴或 Windows 终端可用 |
| `config/busybox-1.38.0.config` 启用宽字符，关闭组合字符，字符上限为 40959（U+9FFF） | 使用 BusyBox Unicode 清洗/宽度函数的路径会限制字符；不能推导所有字节流输出都会损坏，但必须补中文、组合字符、emoji 测试 |
| `FEATURE_SH_STANDALONE` 与 `FEATURE_PREFER_APPLETS` 开启 | 宿主命令发现和内置命令选择需要显式设计；`command -v xz` 不足以证明找到了外部编码器 |
| `wget.c` 的 Cosmopolitan 补丁跳过 OpenSSL helper，内置 TLS 路径明确提示未实现证书校验 | HTTPS 连通性不等于已验证服务器身份；可信下载是新增 P0 能力缺口 |
| smoke/deep 中仍有管道只判断末端输出、SOFT 不阻断，以及 `vi --help` 只测存在的情况 | 现有测试通过不是完整语义或交互验收，不能直接生成“所有功能支持”表 |
| smoke/deep 的临时目录创建循环没有失败上限；清理使用切换目录前的相对路径 | 只读目录可能长时间重试，清理可能找错位置；纳入测试基础设施修复 |
| 当前 CI 的 min 嵌套用例主要在 Linux x86 构建任务执行；Windows 从 PowerShell 执行二进制 | full/min、安装入口、cmd/Git Bash、真实终端体验还需分别取证 |

源码依据：`patches/busybox-cosmo-full.patch` 的 `networking/wget.c` 差异；生成树 `work/busybox-1.38.0-x86_64/networking/wget.c` 的 `spawn_ssl_client()`；锁定 BusyBox 源码 `libbb/unicode.c` 的 `wcwidth()` 与字符清洗逻辑。生成树仅用于核对，修改仍落在权威补丁与配置中。

上一轮示例应作如下修正：

- `busybox xz -c` 不能作为外部 xz 编码能力探针。必须先定位明确的外部程序，再测试该程序，并记录来源。
- `stty size` 成功仅证明可以获取尺寸，不证明 ANSI、原始输入或恢复正确；失败也不意味着不能输出颜色。
- `stty` 修复须覆盖 Linux/macOS/Windows 的实际 Cosmopolitan 布局，不能直接假设 Linux 原生索引在所有相关结构里都正确。
- 临时目录不能无条件退回当前目录；只读目录是正常部署场景。创建失败需要有界退出。
- 配置中存在 applet 只代表编译入口存在。支持声明必须细到具体操作，例如 `archive.xz.decode` 与 `archive.xz.encode`。

## 3. 分层与实现边界

| 层 | 职责 | 优先实现方式 |
|---|---|---|
| 启动层 | 定位发行包、选择架构、缓存、副本转换、loader、执行脚本 | 统一现有 launcher；Windows 提供原生可调用入口 |
| 能力层 | 区分内置/外部实现、支持状态、依赖、验证证据 | 构建清单 + 按需运行探针 |
| 脚本层 | 参数、路径、临时目录、错误、下载、任务管理 | 小型 POSIX 风格 Shell 库 |
| 交互层 | 菜单、输入、进度、终端生命周期 | 行式 Shell 优先；完整 TUI 评估小型 C 辅助程序 |
| 底层适配 | termios、exec、句柄、ABI 与 syscall 缺口 | BusyBox/Cosmopolitan 补丁与上游贡献 |

纯 Shell 适合业务编排和低频交互。完整 TUI 若逐键调用外部进程、反复执行 `stty`，会增加延迟并使状态管理复杂。建议在终端修复后做一个小型 C 辅助程序原型，让它在一次交互期间持有终端、解析按键、计算显示宽度、完成恢复；业务仍由 Shell 完成。

辅助程序先作为可选发行组件，测过体积、启动成本和维护负担后，再决定是否集成为 applet。第一阶段只需要选择器、文本输入、确认和进度，不建设通用窗口系统。不因某个现有 TUI 库接口好用就默认其已支持 Cosmopolitan；引入前需验证构建、许可、终端与体积。

## 5. 能力清单与脚本 API

能力分开记录“实现可用性”和“验证状态”：

- 可用性：`builtin`、`external`、`unsupported`、`unavailable`。分别表示内置实现、外部依赖、语义不支持、本机条件不足。
- 验证状态：`verified`、`known-broken`、`unverified`。保留验证时间、用例 ID、提交、产物 SHA256、平台/架构、启动方式。
- 运行环境条件：TTY 是否存在、当前目录是否可写、外部编码器路径、网络条件。与静态 applet 清单分开。

运行诊断入口首版已经提供以下接口；下载和任务管理接口仍按工作包逐步加入：

```sh
bbcosmo run app.sh --参数
bbcosmo capabilities --format json
```

`bbcosmo` 是兼容层的独立入口，避免改变 BusyBox 已有 applet 参数。Unix 和 Windows 的具体入口封装允许不同，但参数语义和错误结果应一致。

首批库接口使用 `bbp_` 前缀：`bbp_require`、`bbp`、`bbp_tmpdir`、`bbp_ui_mode`、`bbp_ui_select`、`bbp_ui_confirm`、`bbp_xz_encode_available`。下载、任务管理和更高层的 `bb_fetch`、`bb_task_run` 等接口等 R04/R09 验收后再加入。第一版只实现由示例应用真实使用的接口，不提前包装全部 applet。

约定：

1. `bb_run` 指向启动器验证后的运行入口，避免每条命令重复做缓存转换；内置 applet 与外部依赖走独立路径，不串成 `eval` 或 `sh -c` 字符串。
2. 清单既记录 `applet.xz`，也记录 `archive.xz.encode`；`http.fetch`、`https.peer_verified`、`tty.size`、`tty.raw`、`term.cursor` 分开。
3. 构建期生成 JSON 清单；Shell 通过库查询，不要求用户安装 JSON 解析器。外部命令和路径值不以可执行 Shell 代码输出，避免 `source`/`eval` 载入探测结果。
4. 不隐式修改宿主 PATH、Shell 启动文件、全局 locale、trap 或 `set -e`。需要生命周期管理的接口由顶层驱动统一持有。
5. 兼容层定义自己的少量错误码：成功、操作失败、用法错误、能力缺失、取消、超时；保留底层原始退出码供诊断。不能改变 `grep` 等 applet 自身退出码语义。
6. 探针按需运行，有超时；普通启动不访问外网、不改真实终端参数、不需要管理员。完整诊断把有副作用的测试限定到临时目录/独立 PTY。
7. 构建清单可持久化；外部工具探针缓存需随工具身份、PATH、产物更新失效。终端会话能力每次重新判断，不跨 SSH/终端进程复用。

## 6. 终端体验细则

### 6.1 自动选择与用户控制

采用 `--ui=auto|line|tui|none` 与 `--color=auto|always|never`，允许用户覆盖自动判断。`auto` 在没有交互输入时进入非交互模式；强制 `tui` 但条件不足应给出明确原因。`none` 缺必需参数时立即失败，不能悄悄采用有副作用的默认值。

分别检查输入流、显示流和结果流。选择器可以把结果输出到 stdout，把界面输出到终端/stderr；stdout 被重定向时不污染结果。通常没有交互终端就不提示；高级的“从终端读输入、向管道写结果”由显式模式启用。

`NO_COLOR` 非空时默认关闭颜色，但不自动禁用菜单或光标功能；明确的命令行设置具有最高优先级。这遵循 [NO_COLOR 约定](https://no-color.org/)。

### 6.2 输入与恢复

- 默认键位统一：方向键和 j/k 移动、Enter 选择、Esc 返回、Ctrl-C 取消；文本输入状态下 j/k 仍是文本。
- Esc 与方向键序列存在歧义，按键解析采用可配置超时；覆盖分片到达的字节、慢速 SSH、EOF、CR/LF 和不同退格编码。
- 粘贴按文本事件处理，不把一段粘贴解释成连续菜单动作；能力允许时使用 [xterm bracketed paste](https://www.invisible-island.net/xterm/ctlseqs/ctlseqs.html)。
- 进入交互时保存状态，退出时恢复自己改过的终端模式、回显、光标、备用屏幕和粘贴模式；注册后执行命令、正常退出、可捕获信号、子程序失败都覆盖测试。
- 强制杀死和系统崩溃无法承诺应用自行恢复；提供独立 `doctor --terminal-reset` 恢复入口，不以日常启动自动重置终端代替精确恢复。
- Windows 需要验证 Console 模式及 VT 输入输出；`TERM` 字符串只作为提示。微软文档明确区分 [VT 输出与输入模式](https://learn.microsoft.com/en-us/windows/console/console-virtual-terminal-sequences)，因此颜色可用不能推导按键可用。

### 6.3 中文、布局与可访问性

当前 U+9FFF 上限与组合字符关闭影响使用 BusyBox Unicode 宽度/清洗函数的路径。先盘点 `ash` 行编辑、`ls`、`vi`、`less` 和自建 UI 的不同输出路径，再评估调整配置和字符表，避免把一次 `printf` 输出成功当成完整 Unicode 支持。

布局按屏幕列宽计算，不能直接使用字节数、`${#text}` 或 `wc -m`。删除和截断需考虑字素边界；字素不等于固定显示宽度，实际字体/终端仍影响结果。[Unicode UAX #29](https://www.unicode.org/reports/tr29/) 为字素分割提供基础规则。

第一阶段使用中文说明、ASCII 边框与文本状态，不让 emoji 承担必须对齐的图标职责；测试中文、全角符号、NFC/NFD、组合音标、emoji/ZWJ、窄窗口、长文件名。显示回退只作用于渲染副本，保留原始文件名和数据。菜单返回稳定 ID，不能用显示文字定位真实文件。

状态同时有文字，不只靠红绿颜色；支持无动画、行式输出和可复制日志。展示来自文件名、日志或网络的文本时转义控制字符，避免它们改变光标或伪造界面。

### 6.4 速度与反馈

初期测量冷启动、热启动、按键到下一帧、长列表滚动和取消耗时；分别保存 Linux/macOS/Windows 数据。建议先以本地按键响应 p95 小于 100ms、普通取消反馈小于 1 秒作为设计目标，采得真实基线后再决定门禁，不能当作当前承诺。

绘制尽量合并写入，更新变化行；空闲时阻塞等事件，避免轮询和每帧启动一串 `sed/awk/stty`。长任务尽早显示阶段和可取消状态；未知总量显示阶段文字，不伪造百分比。Windows 尤其要减少短命子进程。

## 7. 文件、下载与进程的统一体验

| 差异 | 统一策略 | 保留的真实限制 |
|---|---|---|
| Windows 路径、UNC、盘符、MSYS 参数转换 | 外部程序调用边界显式转换；参数数组/argv 往返测试 | 不全局替换反斜杠，不将 WSL 当成原生 Windows |
| CRLF/BOM | 脚本模板统一 UTF-8 无 BOM、LF；输入格式由业务声明 | 不擅自重写用户文件或二进制 |
| 文件名含空格、换行、通配符、前导短横线 | 不解析 `ls`；使用经测试的 NUL 流/逐参数调用；显示名与原路径分离 | Shell 变量不能保存 NUL；遇到不可表示路径需明示 |
| 临时目录与缓存 | 环境约定目录中原子创建独占目录、有界重试、绝对路径清理、退出码保留 | 不假定 cwd 可写；权限语义依平台验证 |
| 文件更新 | 在目标目录写临时文件、校验后替换；保留原文件直到成功 | 跨文件系统移动、Windows 已打开文件、持久化保证不能伪装一致 |
| 权限、属主、符号链接 | 先声明是否为业务必需；不支持时准确失败或选择明确的复制模式 | 不用 chmod 返回 0 假装敏感数据访问权限已落实 |
| gzip/bzip2/xz | gzip 为便携默认；xz 创建显式依赖已验证外部编码器 | 不把失败文件当归档，不静默更换用户指定格式 |
| 下载 | 固定可验证后端、超时、有限重试、临时文件、状态码与内容检查 | 无合格 TLS 后端就没有“可信 HTTPS”；不得静默关闭证书验证 |
| 进程与取消 | 应用自建任务 ID，追踪启动的子进程；能力允许时用进程组/Windows 对应机制 | 纯 Shell 不保证任意进程树终止；不能按名字误杀其他程序 |
| 进程信息 | 规范化少量有定义字段，额外字段可空 | 不要求 Linux `/proc` 与 macOS 系统 ps 输出相同 |
| 服务端 socket/fork | 单独验证 listen/accept/继承/关闭，多连接与超时 | Windows 已知缺口不能用客户端连接成功覆盖 |

格式化结果与业务解析分离。机器输出使用固定字段与约定的时间/数值格式，人类输出可本地化；不会通过全局 `LC_ALL=C` 假设所有 Unicode 行为已统一。

## 8. CI 如何验收体验

不全量相乘所有环境。保留现有 OS/架构矩阵，增加能暴露差异的分层任务：

1. 每次 PR：脚本契约、能力清单、缺依赖/错误生产者/退出码/只读目录等负向用例，full/min 的核心业务示例；所有测试自带超时。
2. Unix 终端：Linux/macOS 的独立 PTY；注入按键、分片转义序列、粘贴、EOF、窗口缩放；用独立观察器检验 termios 槽位与退出后的恢复。
3. Windows 终端：专门的 Console/ConPTY 驱动；PowerShell 重定向运行只算批处理验收。验证 UTF-8 往返、VT 模式、取消、粘贴和结束时句柄清理。
4. 发布候选：零安装/安装后、full/min、空 PATH 或受控 PATH、冷/热/损坏缓存、并发首跑、只读包目录；对 payload 架构与启动链取证，不能只记录宿主 `uname`。
5. 定期/手动：64K 内核、SSH/tmux、Windows Terminal 与 macOS Terminal 的人工体验走查、较大数据与性能趋势。字体、输入法和真实视觉体验不能只由 CI 字节流断言代替。

ConPTY 通道需要持续读取并正确关闭句柄；微软的 [会话创建文档](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session) 特别说明同步 I/O 与关闭过程可能死锁。驱动测试自身也要有超时和结束断言。

每项输出 PASS、FAIL、SKIP、XFAIL、XPASS 或基础设施错误。声明支持的能力缺失或退化必须阻断；已知问题按具体用例登记，不能整组 SOFT。预期失败意外通过时触发基线更新核验，避免旧限制永远留存。

测试交互契约优先于逐字节金文件：同样操作选择相同 ID、取消不提交、粘贴不触发多次动作、结果流不含 UI 转义、输出没有越界、退出后终端恢复。帧快照测试去除时间/路径/光标闪烁等噪声，人工验证真实终端渲染。

## 9. 实施顺序与阶段交付

| 阶段 | 主要内容 | 可验收成果 | 相对工作量 |
|---|---|---|---|
| S0：明确现状 | R01/R03，建立 TLS 与 termios 缺口记录，收敛矛盾文档 | 机器可读能力表、可靠负向测试、支持范围说明 | 中 |
| S1：脚本可用 | R02/R04/R06/R07，文件适配的必要部分 | 同一脚本跨平台启动、下载、处理文件、行式交互、非交互运行 | 大；TLS 后端选择影响范围 |
| S2：终端正确 | R05/R10 与 PTY/ConPTY 驱动 | 中文/按键/终端恢复的可复核结果，完整 TUI 允许启用的平台清单 | 大，技术不确定性最高 |
| S3：交互完善 | R09/R11，低闪烁、长列表、取消、缩放 | 可选全屏界面，与行式业务结果一致，性能基线 | 中到大 |
| 持续维护 | R08/R12/R13、上游贡献、升级演练 | 支持矩阵随发行生成，补丁可追踪和退出 | 持续 |

这些是工作规模评估，不是日历承诺。S1 可交付行式体验，不必等待 S2 的全部终端修复；在可信下载后端就绪前，示例的下载功能明确不可用。Windows 原生 ARM64、完整 Unix 服务管理、全套终端控件、鼠标和复杂 emoji 排版不作为首版门槛。

首个示例建议做“归档检查与解包向导”：选择本地包或可信下载来源 → 检查摘要与包条目 → 选择目标 → 执行 → 显示结果/日志。使用专用目录，覆盖恶意路径、覆盖冲突、只读目标、取消与无 xz 编码器；核心路径使用 gzip，xz 创建作为可选功能。它能同时验证路径、UTF-8、下载、归档、错误、进度与界面，而不依赖平台专用系统管理功能。

拟议目录：`lib/portable/` 放脚本接口，`tools/bbcosmo/` 放入口及可选原生辅助程序，`tests/contract/` 放行为契约，`tests/terminal/` 放 PTY/ConPTY，`examples/` 放同一个示例的交互与非交互入口。能力规格使用一个权威文件；CI 与文档从它生成支持表。

下一轮最小实施批次为 R01/R02/R03/R06/R07，并同时推进 R04 的后端验证：先交付能稳定启动、报告能力、创建临时目录、准确失败、显示行式菜单的脚本底座，再逐项接入下载与完整 TUI。
